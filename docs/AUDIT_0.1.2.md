# Технический аудит 0.1.2 — 14 октября 2026

Исторический отчёт: A-01/A-02/A-03 закрыты в [повторном аудите 0.1.3](AUDIT_0.1.3.md).

База сравнения: `56c623f` (0.1.1). Проверены новый UI и его модель, история,
согласие на отправку отчёта, AIProviderManager/NetworkAIProvider, MCP-мост,
структурная обработка Harness YAML, сканер накопителя и упаковка.
Это проверка исходников и локальных тестов, не внешний penetration test.

## Найденные существующие замечания

### A-01 — нет повторной проверки endpoint в streaming

Средняя важность, высокая уверенность по исходникам.
`Sources/MacAssistantCore/Services/AI/NetworkAIProvider.swift:38`:
`send` и `availableModels` вызывают AIEndpointValidator, но `stream` строит
запрос непосредственно. Обычно профиль проверен при сохранении, однако
загруженный или переданный напрямую некорректный профиль обходит этот барьер.
При HTTP-адресе это может привести к отправке ключа и сообщения без HTTPS.
Рекомендация: валидировать профиль до загрузки ключа и построения streaming-
запроса; добавить отрицательный тест без сетевого доступа.
Фактическая утечка не воспроизводилась и не утверждается.

### A-02 — преждевременный конец SSE считается успехом

Средняя важность, высокая уверенность по исходникам.
`Sources/MacAssistantCore/Services/AI/NetworkAIProvider.swift:49`:
цикл завершает поток успешно при EOF даже без `[DONE]` или иного подтверждения
завершения ответа. Некорректные data-кадры также пропускаются через `try?`.
При таком завершении частичный ответ может считаться полным, и UI уберёт повтор.
Рекомендация: отслеживать подтверждение окончания согласно контракту API,
различать служебные кадры и повреждение ответа; покрыть неожиданное EOF тестом.
Проверка с реальными провайдерами не выполнялась.

### A-03 — замена Keychain-записи не атомарна

Средняя важность, высокая уверенность по исходникам.
`Sources/MacAssistantCore/Services/AI/AIProviderManager.swift:16`:
старое значение удаляется до SecItemAdd. Если добавление завершится ошибкой,
старый ключ уже утрачен и пользователю потребуется ввести его снова.
Рекомендация: обновлять существующую запись через SecItemUpdate, добавлять только
при errSecItemNotFound; проверить сохранение старого значения при ошибке.
Сбой реального Keychain намеренно не вызывался.

Эти механизмы существуют в базе 0.1.1, не изменены в блоке оформления и требуют
отдельного исправления. Поэтому проекту не присвоен безусловный статус «аудит
без замечаний», несмотря на успешные тесты нового интерфейса.

  `codesign --verify --deep --strict` проходит, бинарник совпадает с исходным bundle.

## Ограничения проверки

Реальные API и внешний Harness не запускались. Клавиатурный ввод, popover,
VoiceOver и прокрутка в живом окне не прошли автоматизированный end-to-end тест:
снимки подтверждают отрисовку, но не заменяют интерактивную проверку.
Контраст использует семантические цвета macOS, отдельный численный WCAG-аудит
не проводился. Установщик arm64, unsigned, без notarization; в payload есть
служебные AppleDouble-записи среды сборки.
