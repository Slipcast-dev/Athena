## Выполненные задачи

- Изучено единое техническое задание версии 1.0.
- Проверено исходное состояние рабочей папки: проектных файлов и зависимостей не было.
- Инициализирован Git-репозиторий с основной веткой `main`.
- Определён стартовый стек: Swift 5.9+, SwiftUI, macOS 14+, Swift Concurrency, XCTest и Swift Package Manager.
- Сформирован план поэтапной реализации с обязательными контрольными точками.
- Создан Swift Package с библиотекой `MacAssistantCore` и исполняемым приложением `MacAssistant`.
- Созданы типобезопасные модели для диагностики, накопителя, ИИ-провайдеров, чата и задач агента.
- Определены протоколы системной диагностики, анализа накопителя, ИИ-провайдера и Agent Bridge.
- Добавлен контейнер зависимостей с безопасной реализацией отсутствующих сервисов.
- Добавлены начальные XCTest-проверки контейнера и расчёта заполнения накопителя.
- Создан `NavigationSplitView` с семью русскоязычными разделами приложения.
- Каждый раздел вынесен в отдельный SwiftUI-экран, а повторяющиеся состояния готовности, загрузки и ошибки — в `FeatureScreen`.
- Добавлено отдельное системное окно настроек и ссылка на него из обзора настроек.
- Создан сценарий `script/build_and_run.sh`, формирующий локальный `.app`-пакет, и конфигурация кнопки запуска Codex.
- Реализован локальный сбор модели Mac, версии macOS, архитектуры и числа ядер CPU через системные API macOS.
- Реализован расчёт загрузки CPU по разнице двух последовательных Mach-снимков.
- Реализован сбор показателей RAM и системного накопителя без `sudo` и внешних процессов.
- Реализованы структурированный диагностический отчёт, документированные пороги и русскоязычные рекомендации.
- Дашборд обновляет локальные показатели с интервалом 5 секунд, пока его экран активен.
- Реализован выбор каталога через `NSOpenPanel`, безопасное сканирование и поиск файлов от 100 МБ.
- Символические ссылки и недоступные элементы не обходятся; сканирование можно отменить.

## Известные риски и ограничения

- Сведения о протоколе, аутентификации и MCP-совместимости DeepSeek Harness в ТЗ не определены. Интеграция не будет проектироваться на предположениях.
- Показатели нагрузки CPU необходимо рассчитывать по двум последовательным измерениям; единичный снимок не является корректной метрикой.
- Операции со сканированием файлов должны выполняться только для каталогов, явно выбранных пользователем, с соблюдением ограничений macOS TCC.
- Memory pressure отображается как недоступный, поскольку текущая реализация не использует источник, достаточный для его достоверной классификации.
- В MVP не создаются security-scoped bookmarks: приложение сканирует каталог только во время пользовательского выбора в текущем сеансе.
