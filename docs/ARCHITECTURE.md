# Архитектурный план Mac Assistant

## Подход

Приложение будет строиться как нативное приложение macOS на SwiftUI с архитектурой MVVM и отдельным слоем сервисов. Зависимости сервисов будут вводиться через протоколы и единый контейнер приложения. Такой подход отделяет интерфейс от системных вызовов, упрощает тестирование и не связывает логику с конкретным поставщиком ИИ.

## Планируемые слои

| Слой | Назначение |
| --- | --- |
| `App` | Точка входа, контейнер зависимостей и жизненный цикл приложения. |
| `Models` | Независимые модели диагностики, хранилища, чата и провайдеров. |
| `Services` | Изолированная работа с macOS, файловой системой, Keychain, сетью и внешними агентами. |
| `ViewModels` | Состояние экранов, запуск отменяемых задач и преобразование данных для UI. |
| `Views` | SwiftUI-интерфейс без бизнес-логики. |
| `Tests` | Модульные тесты сервисов и view model с мок-объектами. |

## Реализованный каркас

- `MacAssistantCore` — библиотека с моделями, сервисными контрактами и `AppContainer`.
- `MacAssistant` — исполняемая SwiftUI-точка входа; до блока интерфейса отображает нейтральное состояние готовности.
- `ServiceDependencies` — неизменяемый набор зависимостей. Его можно заменить тестовыми реализациями без изменения SwiftUI-экранов.
- Реализации сервисов пока явно возвращают `ServiceError.unavailable`: это предотвращает появление вымышленных метрик до реализации блока диагностики.

## Интерфейсный слой

- `ContentView` владеет выбором раздела в рамках окна через `SceneStorage` и собирает `NavigationSplitView`.
- `SidebarView` использует нативный стиль боковой панели macOS и стабильные идентификаторы `AppSection`.
- `FeatureScreen` задаёт единообразную основу для состояния загрузки и безопасных пользовательских ошибок, без вывода технических деталей.
- Экраны разделены по каталогам `Views`, поэтому добавление ViewModel не приведёт к размещению бизнес-логики в SwiftUI-представлениях.

## Границы безопасности

- Ключи API хранятся только в Keychain и никогда не включаются в журналы, отчёты или историю чатов.
- Анализ накопителя не удаляет файлы и не обходит ограничения TCC.
- Ответы ИИ и команды внешнего агента считаются недоверенными входными данными.
- Внешний агент получает только строго определённые операции после локальной проверки разрешений.
- Перед отправкой диагностического отчёта в облачный ИИ пользователь увидит обезличенный предварительный просмотр и даст явное согласие.
